How do I get access to Cloud workspaces? └
Cloud workspaces are available to users on Pro, Teams, or Enterprise plans.
What are the differences between Pro, Teams, and Enterprise plans? └
Our Pro plan is for individual users who want to get the most out of Conductor. Pro gets you access to cloud workspaces and all of our latest features like the Conductor API, our mobile app, and a whole lot more coming soon.
Our Team plan gets you all of Pro’s features to use across your company. And now with Conductor Multiplayer, users in the same Conductor org can collaborate live by sharing workspaces and prompting agents in real-time together. Our Team plan also provides centralized billing and an admin portal to manage user roles within your org.
Our Enterprise plan has all of Teams’ features with the additional security and privacy controls large organizations expect like automated user provisioning, SLA for dedicated support, and fine-grained security controls.
How do I sign up my company for a Team plan? └
Team plans are currently invite-only. If your company is interested in purchasing a Team plan, you can reach out to us here: https://www.conductor.build/team-plan
Do I have to use API keys to set up inference in cloud workspaces? └
No, just like local Conductor, you can bring your own subscriptions and/or API keys for cloud workspaces.
Do I have to pay an additional fee for cloud workspaces? └
Not right now, but we plan to introduce usage-based pricing for cloud compute in the future.
How are cloud workspaces different from local workspaces? └
When you create a cloud workspace, we automatically create a Vercel sandbox for your agent to run in. Your agent works in the cloud so that even if you close the Conductor app, work continues.
In contrast, local workspace sessions run on your local machine. When your machine shuts off or you close the app, sessions terminate.
What are the hardware specs of the sandboxes? └
Each machine has an 8 core CPU with 16GB of RAM.
What comes pre-installed on the sandboxes? └
Each machine runs Amazon Linux 2023 with the following software pre-installed: Node.js 24, npm, pnpm, Python 3, git, GitHub CLI, jq, ripgrep, git-lfs, tmux, and vim. Users are able to install additional software to their machines by configuring their cloud settings.
Where can I learn more about Vercel sandboxes? └
https://vercel.com/docs/sandbox . Conductor Cloud was built in close collaboration with Vercel .
Where are cloud workspaces hosted? └
Our cloud workspaces are hosted in Vercel sandboxes based in the us-east-1 region .
Does Conductor have access to my data in cloud workspaces? └
Yes. Unlike with local Conductor sessions, chat messages sent in cloud workspaces are stored on Conductor’s servers.
Can you explain why data privacy is different between Cloud and Local Conductor? └
With local Conductor, your messages are sent directly to your coding model provider, and session data is stored on your device. Conductor never accesses your coding inputs / outputs.
With Cloud Conductor, sessions run in managed cloud sandboxes rather than on your device. As a result, Conductor must store your session inputs and outputs on our servers to facilitate activity in cloud workspaces.
Has Conductor completed a SOC 2 Type II audit? └
Yes. Conductor holds a SOC 2 Type II attestation. The full SOC 2 audit and our annual penetration test reports are available upon request through our trust center: trust.conductor.build
Can I use my own cloud machines instead of Conductor’s? └
Not at the moment, but our team is hard at work building a self-hosted cloud offering. If you are interested in exploring this as part of an Enterprise plan, please reach out to us here: https://www.conductor.build/enterprise
