The fastest developer workflow for every AI coding agent.
agent-manager is a Go terminal UI on top of tmux that runs every AI coding agent side by side.
Everything is one keypress: spawn one in a sentence, answer a blocked one
without attaching, review its diff without leaving the list. Each session runs your own
installed CLI as-is: your login, your config, your MCP servers, every feature it ships.

The eleven, and how a new one gets in .
The manager registers its own MCP server into every MCP-capable session it spawns, so the agent can
drive the workspace: spawn a teammate, send it a message, wait until it is done, and open
a terminal the user can watch. How registration works .
create_session Starts another agent on a named task, in its own worktree if the work needs one.
send_session Queues a message for another agent, delivered once it is at rest.
create_terminal Opens a shell under the caller for work the user should see.
review Declares the repo, merge base and diff scope so review opens in the right place.

Questions
What is agent-manager? agent-manager is a terminal UI written in Go that runs every AI coding agent as a live tmux session. Each row in its list is a real tmux session running a real coding CLI, coloured by what that CLI's pane is doing, so a fleet of agents is read, answered and reviewed from one screen.
Which coding CLIs does agent-manager support? Eleven, as of v0.40.0: Claude Code, OpenCode, Codex, Grok Build, Gemini CLI, Antigravity CLI, Pi, Command Code, Hermes Agent, Muse Code and Oh My Pi. Each one's launch command, resume and fork commands, MCP registration and status rules are built into the binary, so an upgrade brings the current version of all of them. Hermes, Antigravity and Oh My Pi have no fork. A CLI outside that list is a feature request, and the CLIs row in Settings opens one prefilled.
Can each session run on its own model? Yes, since v0.40.0. The new-session form has model and effort rows, plus a profile row for a CLI that has profiles, and quick prompt mode picks the same with ctrl+l, ctrl+x and ctrl+y. agent-manager spawn takes --model, --effort and --profile. The lists are read live from each CLI, so a model the CLI ships tomorrow shows up without an agent-manager update. Each CLI keeps your last picks, and the choice is saved on the session, so restart, revive and fork run on it.
What does agent-manager cost? Nothing. It is free and open source under the Apache-2.0 licence, with no account, no licence key and no paid tier. The coding CLIs it runs are billed by their own vendors.
What licence is agent-manager under? Apache-2.0, since v0.19.0 on 4 August 2026. Releases up to v0.18.0 shipped under MIT, which is why write-ups from July 2026 list MIT. The LICENSE and NOTICE files, GitHub's licence detection and the Homebrew and AUR packages all say Apache-2.0.
Does agent-manager support the mouse? Yes, since v0.38.0. The wheel moves the cursor, a click focuses a session (a double click in the full-screen layout), a row drags by its handle to reorder it or move it into another group, and the menu at the end of every row opens its actions. The divider between the list and the preview drags. In a focused pane a drag selects and copies text, and a click on a link opens it. Settings has a mouse toggle that hands native selection back to the terminal.
Which platforms does agent-manager run on? macOS and Linux on both amd64 and arm64, and Windows through WSL2. It needs tmux 3.1 or newer and git.
How do I install agent-manager? brew install agent-manager on macOS or Linux, from homebrew-core. There is also a Homebrew cask for the prebuilt binary, an install script, an AUR package, mise, go install, and prebuilt binaries for every release.
Can an agent drive agent-manager? Yes. The binary carries an MCP server that registers into every MCP-capable session it starts, so an agent can spawn other agents, message them, wait on them, claim shared tasks, reserve files and drive terminals on the developer's own machine.
Does agent-manager replace Claude Code, Codex or OpenCode? No. It starts the CLIs you already installed, with their login, config, MCP servers and features unchanged. It reads each pane the way a human would, or Claude Code hook events, and colours the row by what that CLI is doing.
How does agent-manager compare to herdr and plain tmux? agent-manager is a Go TUI on tmux, so sessions stay alive if you quit it and you answer or review from the list. herdr replaces tmux with its own runtime. Plain tmux keeps sessions alive but cannot tell which agent is blocked. The feature table is at https://agent-manager.dev/compare/.
How is agent-manager different from a Claude Code tmux session picker? A picker such as tmux-claude-hatch or claude-tmux lists the Claude Code sessions in tmux and jumps to one. agent-manager runs eleven coding CLIs, answers a session without attaching, revives a dead one on its own conversation, and reviews its diff with line comments that go back to the agent. The pickers are lighter, and they find Claude sessions you started by hand. The comparison, lazyclaude and ccmux included, is at https://agent-manager.dev/compare/#claude-code-tmux.
Can I run several coding agents at once? Yes. That is what it is for. Each agent is its own tmux session in one list, grouped by project, with live status so you can see which is working, which is waiting on you, and which has finished.
Does agent-manager send my code or prompts to a cloud service? No. It is a local binary. Sessions run on your machine as tmux sessions. Nothing about your sessions, prompts, code or repositories is sent anywhere. The coding CLIs you start talk to their own vendors; agent-manager does not proxy them.
